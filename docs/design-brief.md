# StudyFlow AI 项目设计简报

> 按 `AI_Web_Design_Knowledge_Base_v3/10_PROJECT_BRIEF.md` 填写。用于后续页面设计、视觉升级与验收。未由用户明确提供的项目，标注为「合理默认，可调整」。

## A. 产品

- 名称：StudyFlow AI
- 一句话价值：把大目标拆成今天能完成的一小步。
- 目标用户：16–30 岁学生、自学者和转行者；有明确学习目标，但容易被计划规模和拖延压住。
- 核心任务：输入目标 → 获得可执行计划 → 完成今天任务 → 看到真实进度 → 用自然语言调整计划。
- 网站类型：AI-native Product / SaaS Tool / 学习工具。
- 主要页面：Landing、登录、注册、Dashboard、计划列表、计划详情、新建计划、任务、统计、设置、404。
- 线上地址：https://studyflow-ai-hntk.onrender.com

## B. 艺术指导

- 主风格：**D. Human Warmth / Soft Technology**
- 辅助风格：**Quiet Precision**、**AI-native Interface**
- 核心视觉母题：**成长轨迹 / 今天向前一小步**
- 情绪关键词：平静、可信、温和、专注、有掌控感
- 文化或艺术参考：当前不绑定特定文化符号；如引入文化参考，必须按 `02` 的四步法研究、抽象、转译、校验。
- 主色/辅助色：沿用 `tokens.css` 的暖白底、低饱和薰衣草、薄荷、蜜桃、天蓝。
- 字体倾向：Inter / SF Pro / PingFang SC / Noto Sans SC 中文优先字体栈；展示标题与正文使用同一家族的不同字重。
- 视觉冲击强度：克制到中等。
- 不希望出现的模式：通用 SaaS 三列卡片、整站玻璃拟态、霓虹、无意义 3D/粒子、假数据、低对比灰字、滚动劫持、复制 Apple 页面。

## C. 内容与功能

- 首屏必须传达：这是一个能真正生成并管理学习计划的 AI 工具，而不是聊天玩具。
- 核心视觉主体：产品界面本身 / 计划与任务的结构；不需要虚构硬件或 3D 物体。
- 导航：Landing 顶部导航；应用内桌面侧边栏、移动端底部导航。
- 表单：注册、登录、计划创建、任务新增/编辑、设置、AI 调整输入。
- 搜索/筛选：计划状态/科目/搜索；任务状态/计划/优先级/日期/搜索。
- 数据读写：真实 API；计划、阶段、任务、统计、AI 用量。
- 登录/权限：JWT + HttpOnly Cookie；每个接口校验用户归属。
- AI API：DeepSeek；生成预览、保存、自然语言调整预览/应用。
- 必须覆盖的状态：默认、hover、focus、active、disabled、loading、success、error、empty、timeout。
- 真实性与边界：AI 结果必须经服务端校验；失败不伪造结果；实际用时未填写时显示「尚未登记」。

## D. 技术现状

- 框架：Vue 3 + Vite + JavaScript。
- 路由：Vue Router。
- 状态：Pinia。
- 样式：原生 CSS + CSS Variables；`src/assets/styles/tokens.css`、`base.css`、`forms.css`。
- 当前依赖：Axios、lucide-vue-next 等；避免无理由新增重型依赖。
- 后端/API：Express + SQLite（本地）/ Supabase PostgreSQL（生产）。
- 现有功能：必须保留，不无理由重写。
- 设计系统：暖白、低饱和、轻阴影、细边框、圆角但不过度胶囊化；已有完整组件库。
- 允许新增依赖：仅在现有 CSS/SVG 无法合理实现、且收益大于维护成本时。

## E. 动态与性能

- 动效强度：低到中。
- 是否需要滚动叙事：Landing 可以有轻量节奏，不劫持滚动。
- 是否需要 Canvas：默认不需要。
- 是否需要三维：默认不需要。
- 目标设备：桌面 1440、笔记本 1280、平板 768、手机 390。
- 性能优先级：首屏内容优先；不加载重型特效；免费 Render 实例需要控制资源。
- 减少动态：必须支持 `prefers-reduced-motion`。

## F. 验收

### 视觉

- 首屏只有一个明确焦点，价值主张 5 秒内可理解。
- 标题/正文/注释层级清楚；中文标点、换行、字重正常。
- 色彩有语义，强调色不平均分配；材质与阴影逻辑一致。
- 空状态、加载、错误、成功状态完整。
- 移动端重新排版，没有横向溢出。

### 功能

- 注册/登录/退出、计划 CRUD、任务 CRUD/完成、统计、AI 生成/调整可用。
- 所有重要控件有明确行为；表单有标签与错误说明。
- 真实 API 与演示状态不混淆；AI 失败有明确错误与重试。

### 工程

- `npm run build`、`npm run test:unit -- --run`、`npm run test:server` 通过。
- 无控制台错误；静态资源加载正常。
- 键盘可访问核心操作；焦点可见。
- 支持减少动态；移动端触控目标足够大。
- 不泄露 API Key / 数据库连接串。

### 设计质量 rubric

按 `16_APPLE_INSPIRED_DESIGN_SYSTEM.md` 的 8 项评分（目的与层级、原创性、工艺、材质与光、动效、可用性、无障碍、性能），每项至少 4/5 才可称为完成。

## G. 当前默认决策（可调整）

- 视觉升级优先改 tokens 和现有组件，不新建第二套设计系统。
- 页面优先服务「今天做什么」，而不是展示功能数量。
- 保持温和治愈的基调，但避免幼稚化；关键操作要清楚、有反馈。
- 不用 Apple 的具体版式、图片或品牌资产；“Apple-inspired”只取目的、清晰、工艺、连贯与叙事。
